Executive Summary

This project presents an enterprise-grade, concurrent medical telemetry and automated facility management firmware engineered for the Espressif ESP32 dual-core microcontroller. Designed to satisfy all 6 mandatory internship assignments within a single, unified codebase, the system integrates physical sensor acquisition, real-time physiological signal synthesis, role-based cloud publishing via MQTT, closed-loop safety actuation, and an advanced fault-tolerant offline detection and replay engine.

The firmware executes on FreeRTOS Symmetric Multiprocessing (SMP), allocating network protocol stacks (Wi-Fi and lwIP) to Core 0 while dedicating Core 1 exclusively to 12 prioritized application tasks. Inter-task communication is strictly synchronized using thread-safe FreeRTOS mutexes, queues, and semaphores, ensuring zero race conditions. A dual-tier watchdog supervisor couples the hardware ESP-IDF Task Watchdog Timer (TWDT) with an application heartbeat monitor to guarantee unfailing real-time reliability in clinical environments.

Key Project Accomplishments:
  • Unified Single-Project Integration: All 6 assigned internship tasks run simultaneously in one firmware image without blocking delays (0 ms delay()).
  • Resource Efficiency: RAM utilization measured at 15.1% (49,424 B of 327,680 B) and Flash at 79.9% (1,047,106 B of 1,310,720 B).
  • Automated Test Suite: 15 unit tests covering strict numeric string parsers and medication dosage safety clamping compile and pass cleanly via PlatformIO Unity.
  • Open Source & Credentials Safety: Released under the MIT License with complete credential isolation (private keys never committed to Git).

2. Concurrency Model & FreeRTOS Task Scheduling (Task 1)

The system utilizes FreeRTOS Symmetric Multiprocessing (SMP) to execute 12 application tasks concurrently across a strict priority hierarchy. All application tasks are pinned to Core 1, dedicating Core 0 exclusively to Wi-Fi and TCP/IP protocol processing.

Task Identifier Priority Execution Cadence Stack Allocation Task Responsibilities & Synchronization

alertTask Priority 4 Asynchronous (Event) 3072 Bytes Blocks on alertSemaphore; logs rising-edge clinical anomalies.
vitalSensorTask Priority 3 5s to 60s adaptive 3072 Bytes Generates optical PPG (HR & SpO2); adapts interval via samplingRateQueue.
ecgTask Priority 3 Fixed 5 Hz (200 ms) 3072 Bytes Synthesizes real-time cardiac Gaussian waveform morphology.
medicationTask Priority 3 50 Hz (20 ms loop) 3072 Bytes Enforces +10 mg/hr/s slew rate, button debounce, and rapid 3.3 Hz alarm.
bedTask Priority 2 50 Hz (20 ms loop) 3072 Bytes Computes microsecond servo PWM pulse; smoothly slews bed elevation.
envSensorTask Priority 2 1000 ms periodic 3072 Bytes Simulates facility room temp, O2, and AQI with CLI override support.
temperatureTask Priority 2 Non-blocking FSM 3072 Bytes Non-blocking state machine managing DS18B20 750 ms conversion cycle.

samplingTask Priority 2 1000 ms periodic 2560 Bytes Monitors vital health state; commands 5s abnormal vs 30s stable rate.
mqttTask Priority 2 3000 ms round-robin 5120 Bytes PubSubClient transport, exponential backoff, and FIFO offline replay.
displayTask Priority 1 100 ms periodic 4096 Bytes Drains sensorQueue, updates telemetry, renders OLED medication UI.

Inter-Task Synchronization Primitives

  • vitalsMutex: FreeRTOS Mutex (xSemaphoreCreateMutex()) protecting shared clinical telemetry.
  • sensorQueue: 10-slot queue delivering SensorMessage structs from sensor tasks to displayTask.
  • dosageQueue: 5-slot queue routing target dosage commands from MQTT to medicationTask.
  • bedAngleQueue: 5-slot queue routing bed angle commands from MQTT to bedTask.
  • samplingRateQueue: 5-slot queue distributing dynamic telemetry intervals from samplingTask to sensors.
  • offlineBuffer: 64-slot queue storing timestamped telemetry packets during network outages.

5. Comprehensive Implementation of Assignment Tasks

Task 1: Multi-Sensor Expansion Using FreeRTOS

The system concurrently manages physical and simulated parameters. Physical core temperature is sampled via a Dallas DS18B20 1-Wire sensor on GPIO 4 using a non-blocking three-state machine (TEMP_IDLE → TEMP_CONVERTING → TEMP_READ). This ensures the 750 ms 12-bit conversion delay never stalls the FreeRTOS scheduler. Optical Photoplethysmogram (PPG) vitals (Heart Rate 50-100 BPM, SpO2 92-100%) and a 5 Hz Gaussian ECG waveform model are synthesized concurrently. Dual-tier watchdog protection couples the hardware ESP-IDF TWDT (8000 ms) with a software heartbeat monitor cycling every 6000 ms.

Task 2: Dual-Role IoT Monitoring System (Role-Based Dashboards)

The system publishes to 10 dedicated Adafruit IO feeds, enforcing logical separation between clinical and facility personnel:

  • Medical Staff Feeds: hospital-heart-rate, hospital-spo2, hospital-body-temp.
  • Facility Management Feeds: hospital-room-temp, hospital-room-oxygen, hospital-air-quality.
  • Control & Events: hospital-dosage, hospital-bed-angle, hospital-sampling-rate, and hospital-events.

Every 60 seconds, mqttTask computes rolling-window minimum, maximum, and average metrics, publishing an aggregated diagnostic summary to hospital-events (e.g., [SUMMARY] HR avg: 72 bpm | SpO2 avg: 98% | Temp avg: 36.8C | Env: OK).

Task 3: Smart Medication Dosage Adjustment System

Doctors remotely command infusion dosage (0-100 mg/hr) via dashboard slider. The firmware implements a multi-tier safety interlock:

  • Safety Tiers: Normal (0.0 - 79.9 mg/hr, Solid Green LED), Warning (80.0 mg/hr, Solid Yellow LED), and Critical (>80.0 mg/hr).
  • Rate Limiting: Maximum slew rate clamped to +10.0 mg/hr per second, preventing abrupt dosage spikes.
  • Two-Factor Authorization: Any commanded dosage >80 mg/hr clamps the applied rate at 80 mg/hr, blinks the Red LED and pulses the 1200 Hz buzzer rapidly at 3.3 Hz (150 ms period), and prompts PRESS BUTTON on the OLED. The clinician must press the physical button on GPIO 13 within 5 seconds to authorize the dose; otherwise, the request times out safely.

Task 4: Intelligent Remote Bed Elevation Control

Bed elevation is driven by an SG90 servo on GPIO 18 with smooth microsecond pulse interpolation (1.5°/s auto, 2.0°/s manual) to protect patient comfort. The autonomous controller dynamically maps clinical condition to posture:

  • Sleeping Mode (10°): Nominal resting position when vitals are stable.
  • Breathing Support Mode (45°): Automatically triggered when SpO2 drops into the warning band (88% - 91%) to alleviate pulmonary pressure.
  • Emergency Mode (90°): Automatically triggered immediately upon any Critical vital sign (cardiac arrest, extreme hypothermia).
  • Manual Override: Remote slider allows clinicians to set any angle between 0° and 90°.

Task 5: Smart Dynamic Sampling Rate (Adaptive Monitoring)

To optimize battery life and bandwidth, samplingTask dynamically adjusts the telemetry transmission interval based on patient stability:

  • Abnormal State: Instantly accelerates sampling to 5 seconds upon detection of any warning or critical vital sign.
  • Stable State: Automatically relaxes sampling to 30 seconds when vitals return to normal.
  • Manual Override: Dashboard slider permits clinician adjustments between 5 and 60 seconds.

Task 6: Advanced Offline Detection (Fault-Tolerant System)

The firmware continuously monitors Wi-Fi and MQTT connectivity to maintain a tri-state health machine (ONLINE, DEGRADED, OFFLINE):

  • OLED Notification: Inverted status bar on bottom rows (y: 54..63) displays LOGGING OFFLINE without obstructing medication data.
  • Acoustic Discrimination: Wi-Fi failure triggers a rapid double-pip tone (0-100 ms, 200-300 ms ON), while MQTT failure triggers a slow single beep (0-500 ms ON).
  • FIFO Offline Buffer: An in-memory queue stores up to 64 telemetry records (~36.8 KB SRAM). Saturated buffers drop newest records to preserve initial fault telemetry.
  • Exponential Backoff & Replay: Reconnection retry delay doubles from 2s up to 60s. Upon reconnection, all buffered records are drained in FIFO order to Adafruit IO.

Known Architectural Limitations & Design Notes

  1. Multiplexed Event Feed (Adafruit IO Quotas): Due to Adafruit IO's 10-feed limit on standard accounts (6 sensor feeds + 3 control feeds + 1 event feed), all clinical alerts, facility alerts, and 60-second summary reports are multiplexed onto the single shared hospital-events feed.
  2. Logical Role Separation: Role separation between Medical Staff and Facility Management dashboards is implemented at the topic and dashboard layout level rather than through enforced multi-tenant cryptographic access control (RBAC).
  3. Replayed Telemetry Arrival Timestamps: Replayed offline records carry the timestamp of broker reconnection/receipt rather than historic capture time due to Adafruit IO's standard MQTT ingestion format and absence of an onboard battery-backed RTC.
  4. Bounded FIFO RAM Buffer: The offline buffer utilizes an in-memory FreeRTOS queue holding up to 64 records of 576 bytes each (~36.8 KB SRAM). When capacity is reached, it drops newest incoming records to protect initial fault events. It is RAM-only and volatile upon power cycle or hardware reset.
  5. Task Watchdog & SYSTEM_DEGRADED Window: SYSTEM_DEGRADED indicates an internal FreeRTOS worker task has starved its heartbeat while transport remains active. The ESP-IDF Task Watchdog Timer (TWDT) enforces an 8000 ms panic threshold; if a task hangs permanently, the chip resets ~2 seconds after entering SYSTEM_DEGRADED to guarantee fail-safe recovery in medical environments.
  6. Simulated Sensor Telemetry: In simulation mode, physiological vitals (PPG, ECG) and ambient facility conditions (Room Temp, Oxygen %, AQI) are synthesized via mathematical models (e.g. Gaussian superposition) and UART CLI overrides (SET_HR, SET_SPO2, SET_TEMP, SET_ROOM, SET_OXYGEN, SET_AQI).
